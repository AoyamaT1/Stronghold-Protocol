## 一、实施框架：现在到底是怎么接的（三层）

0.2.6 的「侵入式 mod」路线（`node tools/mod.mjs install` 把 `mods/<mod>/data/*.json` 合并进根 `data/`，再手工改
`server/sim/content/index.js`、`bonds.js` 等）在 **0.3.0 升级时被整仓覆盖清空**（棋 350→266、盟约 27→23、`config.assist`
丢失、多处 mod 钩子消失）。现在的路线是 **插件 + 盟约层 + 服主策略** 三层：

| 层 | 放什么 | 位置 | 谁开 |
|---|---|---|---|
| **① 插件层** | 干员（`chess_x_*` 棋子记录）、技能 spec、美术/模型/**语音**（`-look` 包，如 `art/audio/voice/<官方charId>/`）、garrison/effects 记录 | `plugins/<id>/`（content / cosmetic 两类） | 房间默认集（见 ③），房主也可在房间面板改 |
| | 外观包的值**只能是包内相对路径**或 `{ref: <安装清单条目>}`，**不能写 URL**（`shared/plugins/visual.js`）——所以语音文件放包里，别指向 `public/assets` | | |
| **② 盟约层** | 盟约记录（`bonds`）、盟约效果记录（`effects`）、盟约行为代码 | 根 `data/bonds.json`、`data/effects.json`、`server/sim/content/bonds.js` + `server/sim/content/mods/*/bonds.js` | 全局，不需要开 |
| **③ 服主策略** | 每个新房间默认自带哪些插件 | `plugins/config.json`（0.3.0 官方机制） | 全局 |

**为什么盟约不能进插件层（已实测，别再试）**：`shared/plugins/patch.js` 的 `RECORD_MAPS` **没有 `bonds`** ——
`{op:"add",file:"bonds",id:"…"}` 必报 `PLUGIN_RECORD_ID`；`{records:1}` 的支持列表也没有 bonds；脚本插件
（class `script`）只能注册 `kits/enemies/content/meta`。所以 **盟约的数据与行为只能留在②层**，干员留在①层，
两边靠「干员的 `chess.bonds` 指回盟约 id」连接（房间里由内容集 expander 自动把 `chess_x_*` 填进盟约 `members`，
**不要手写 members**）。

当前接好的模组：**罗德岛（rhodes + rhodes-look）、Ave Mujica（ave-mujica + ave-mujica-look）、边狱公司
（limbus-company + limbus-look）、FGO 圆桌（fgo-round-table + fgo-round-table-look）、招募（recruits）** ——
四个自定义盟约（`rhodesShip` / `aveMujicaShip` / `limbusShip` / `roundTable`）都已接回。
`plugins/config.json` 的 `default` 就是这 9 个 id；进任何房间（独立/同盟模拟）都自带，入口（房间顶部
「插件选择 · N」胶囊）只是给房主改动用。

### 语音与官方特效（2026-10-17）

- **语音**：Ave Mujica 5 人已绑定 —— 文件在 `-look` 包内（外观包只允许包内路径），`audio.voice` 与 `audio.voiceJp`
  两棵树都指向同一批文件（这样「语音语言=中文」的默认设置下也能出声，与 fgo/limbus 的处理一致）。其他 mod 的语音用
  `{ref: <安装清单条目>}` 模式（`data/assets.json` 里的语音条目 + `public/assets/audio/voice/**`）。
- **官方特效**：本地特效库（`public/assets/local/fx/**` + `data/local-fx.json` + `fx/index.json` 的 `units`）**没有 mod 干员**
  ——提取时的 `--fx-set used` 只枚举 `data/chess.json`/`backups.json` 里的单位，那时 mod 干员还在 data 里（0.3.0 升级前）。
  绑定本身是自动的：插件棋子的 `assets.spine` = 官方 charId（`art.ref`），客户端 `FxWiring` 的 `unitKey` 会命中
  `fx/index.json` 的 `units[<charId>]`。**只差提取**：
  1. 需要一台装了明日方舟客户端的机器（本机**没装**，只有 `%APPDATA%\Hypergryph` 的启动器配置）；
  2. 建提取环境：`node tools/setup.mjs --local`（生成 `.venv-extract`，需 Python 3.8–3.12 + UnityPy/lz4/Pillow）；
  3. 提取：`.venv-extract/Scripts/python.exe tools/local-extract/extract.py --only fx --fx-set used`
     （`fx.py` 已改成把 `plugins/*/operators/*.json` 的 `art.ref` 一并计入，5 名 Mujica 成员的官方 charId 会自动带上）；
  4. 完事后重启服务器（fx 索引是**静态文件**，客户端 Ctrl+F5；服务器不必重启，但重启一次更稳）。
  注意：技能的官方特效还需要客户端/数据表里有那些技能（插件里用的是简化 spec），`--fx-set used` 至少会给出普攻/命中/阵亡/
  天赋这类挂在 charpack 上的效果。

## 三、可能存在的问题 / 隐患（要盯的）

1. **官方再次升级会再覆盖一遍盟约层**（`data/bonds.json`、`data/effects.json`、`server/sim/content/bonds.js` 都在
   `MANIFEST.json` 里、都会被更新包整文件覆盖）。**升级后必须按 `docs/更新规范.md` §一.3 例外 + §四清单重贴**，
   否则又变成「插件装了但没有盟约」。
2. **MANIFEST 哈希偏差**：②层的三个文件与官方哈希**必然不同**（插件体系补不上盟约，这是已知例外）。若未来更新器改成
   强制校验，可能弹「整包重下」——届时按 §一.3 重贴而不是照它重下（重下会回到纯官方、丢盟约）。
3. **"为了让 doctor/自检变绿"而还原官方文件** —— 2026-10-17 已发生过一次：`public/js/ui/pluginTag.js` +
   `public/css/components.css`（入口「插件选择」，有意偏离）被按官方原件覆盖回去，用户要的入口改名当场丢失。
   **凡是 §一 列的有意偏离（盟约层 + 这两个 UI 文件 + `plugins/config.json`），`node tools/doctor.mjs` 报不一致就是预期**，
   记一笔即可，**不要还原**。改动前后用 `ls -la` 看清 mtime：被还原的文件 mtime 会回到官方包的时间戳
   （如 `Oct 15 23:51`），而正常编辑是当下时间。
4. **`plugins/config.json` 被删或被覆盖** → 所有房间不再默认带模组，用户又只能手动开（甚至找不到入口）。它是**服主文件**，
   不在 MANIFEST 里，升级不会动它——但"清理仓库"这类操作会。
5. **插件 manifest 写错只留一行日志**：`plugins/fgo-round-table/` 就是活例子——服务器把它**静默跳过**，游戏里表现为
   「插件装了但没内容」。**任何插件改动后必须 `node tools/plugin.mjs check`**，并核对启动日志的 loaded/skipped 列表。
6. **内容集是每个房间一份**：`limits.maxSets` 默认 4，且换插件/换模式会让所有成员的页面重新下载校验
   （本次 9 插件 ≈ 十几 MB）。插件组合越多，房间越"重"；别把不用的插件塞进 `default`。
7. **插件房间的对局是"非官方"**：不计入统计总览（这是 0.3.0 的设计，不是 bug）。用户若在意统计，需要知道这一点。
8. **两条路线不能混**：如果将来把干员放回 `data/chess.json`（旧 mod 路线），会与插件里的同名干员**重复**；要走那条路就得
   同时从 `plugins/config.json` 和插件目录里撤掉对应插件，否则进房见两份。
9. **`-look` 包的 `plugin.lock.json`**：改了包内任何文件（含 `art/assets.json` 和新增的语音）都要重跑
   `node tools/plugin.mjs pack <dir>`，否则锁失配；`ave-mujica-look` 的盟约图标与 5 人语音是从安装目录
   （`public/assets/bond/aveMujicaShip.png`、官方素材镜像的 `voice/<charId>/cn_0NN.mp3`）取进包里的（同许可）。
10. **`test/plugins/*.test.js` 只验证「能部署」**：不验证技能/天赋/盟约/语音/特效。别把它当功能验收（见 §四）。
11. **音视频管线的"单位来源"是 `data/`，不是插件**——这是本次踩到的一类坑（语音清单 `tools/build-data.mjs` 与官方特效
   `tools/local-extract/fx.py` 都从 `data/chess.json` / `backups.json` 枚举单位）。插件迁移后 mod 干员不在 data 里，
   这类管线会**静默漏掉**他们。`fx.py` 已补（`plugins/*/operators/*.json` 的 `art.ref` 也计入 `used` 单位）；
   语音目前由 `-look` 包自带文件 + `audio.voice/voiceJp` 绑定（见 §一），不依赖该管线。将来若再有人加"从 data 枚举单位"
   的工具，记得同样带上插件干员。
12. **本机有个只拦 Chrome 的 `.mp3` 直链过滤器**（返回 `204` + `pragma: no-cache`，curl 却是 200；系统代理、SW 都已排除，
   疑似本机安全软件）。**游戏不受影响**：`public/js/media.js` 会把音频改写成无扩展名路径（`/media/…`、`/p/<id>/<hash8>/…`），
   那条路 200 + `Content-Type: audio/mpeg` 且 `<audio>` 能播。**排查音频问题时别被直链 204 带偏**；本机验收音频请用
   改写后的 URL（`scratch/e2e-mujica-voices.mjs` 就是这么做的）。
