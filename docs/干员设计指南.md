# 干员设计指南（卫戍协议：盟约 · 模组开发）

面向在本仓库 `mods/` 里做新干员的人。把「想要什么表现」翻译成「数据 + kit + 引擎原语」，并给出数值标尺与实操步骤。配套参考：`mods/sakiko`（可转向投射物/Fever/免死，含引擎钩子）、`mods/recruits`、`mods/rhodes`、`mods/limbus-company`（数值与叠层）。

---

## 0. 一个干员由三部分组成

1. **数据记录**（`mods/<id>/data/chess.json` 里的一条，安装时并入 `data/chess.json`）——属性、盟约、技能/天赋/特性的文本与**黑板数值（bb）**。
2. **kit**（战斗行为逻辑，JS）——读数据里的 bb，用引擎原语把技能/天赋/特性跑起来。
3. **资源 / 盟约归属**——盟约（`bonds`）、召唤物 token、装备、立绘/音频资源。

数据与 kit 用 **charId** 关联：kit 按 charId 注册，`content/index.js kitOf` 会在该棋子的 `charId` 上找到它（所以同一 charId 的 `_a/_b` 两形态共用一个 kit）。

---

## 1. 数据记录（chess.json 一条的关键字段）

```jsonc
{
  "chessId": "chess_char_6_21_a",   // _a 普通 / _b 精锐(金)，两条
  "charId":  "char_4182_oblvns",    // kit 用它关联
  "tier": 6,                          // 商店阶 I–VI = 价位/强度槽（≠星级 rarity）
  "bonds": ["aveMujicaShip", "preciShip"],
  "stats": { "maxHp": 1850, "atk": 640, "def": 380, "res": 10,
             "cost": 20, "blockCnt": 2, "bat": 1.3, "aspd": 100, "respawnTime": 70 },
  "trait":  { "desc": "...", "bb": { "atk_scale": 0.8 } },
  "talents": [ { "name": "...", "bb": { "def_penetrate_ratio": 0.03, "max_cnt": 10 } } ],
  "skill":  { "skillId": "skchr_x_3", "spType": "...", "bb": { ... } },  // 默认技能
  "skills": [ /* skchr_x_1 / _2 / _3，每条带自己的 spType / spCost / bb */ ],
  "module": { "id": "...", "type": "LOR-Y" }
}
```

- **`bat`**（基础攻击间隔，秒）决定 DPS：`DPS ≈ atk / bat`。调 DPS 优先调 `bat` 或 `atk`。
- **kit 只读 bb**：天赋/技能/特性的所有数值都从 bb 取（`talentBb(chess,i)`、`skillRec(chess,id).bb`、`chess.trait.bb`）。bb 写错 → kit 读到错的数 → 表现异常（祥子之前就是天赋 bb 不对）。
- `_b`（精锐）的属性约为 `_a` 的 ~1.8×（atk/hp）、~1.6×（def），`aspd` +10。改了 `_a` 记得按同比例改 `_b`。

## 2. kit 契约

kit 是一个按 charId 注册的构造函数，返回技能/天赋/特性规格：

```js
export default {
  char_4182_oblvns: (bb, chess, def) => {
    const bbOf = (id) => skillRec(chess, id)?.bb ?? {};  // 每个技能读自己的 bb
    const t0 = talentBb(chess, 0), t1 = talentBb(chess, 1);
    return {
      trait:   { /* 常驻特性 */ },
      talents: [ /* 被动天赋，可挂 buff / 注册 hook */ ],
      skills:  { skchr_x_1: {...}, skchr_x_2: {...}, skchr_x_3: {...} }, // 作者化每个技能
      install(battle, unit) { /* 开场一次性接线：battle.on(...) 等 */ },
    };
  },
};
```

共享助手（`server/sim/content/kits/shared/tier1.js` 等）：`num / talentBb / skillRec / skillBbOf / batMod`、`canTargetEnemy / sortEnemyTargets`（targeting.js）、`frontOf`（dir.js）、`bodyDist`（body.js）。

**kit 常用的引擎 API**（`battle.*`，使用频度从高到低）：
`on`(挂 hook) · `fx`(特效) · `addBuff/removeBuff` · `dealDamage` · `applyStatus` · `after`(定时) · `heal` · `spawnToken`(召唤) · `push/pull`(位移) · `addProjectile`(投射物) · `forceAttack`。

常用 hook（`battle.on('<name>', cb)`）：`hit / damaged / kill / fatal / skillStart / skillEnd / deploy / tick / layerGain`。

**buff mod 键**（`server/sim/buffs.js`）：
- 加算（求和）：`atkPct atkFlat aspd defPct resFlat blockCnt defIgnorePct resIgnorePct spCostPct maxTargets taunt dodgePhys dodgeArts hpRegen rangeExtend` …
- 乘算（连乘）：`atkMul dmgDealtMul dmgTakenMul physTakenMul artsTakenMul healingDealtMul redeployMul` …
- 标志（或）：`stun freeze sleep silence invulnerable unblockable stealth fear bind levitate noSp` …

> 规则：攻击力% 全部**加算**后乘到攻击力上；`dmgDealtMul` 这类是**乘算**，叠在最终伤害上。两者独立——盟约/天赋给的大 atkPct 会再乘一层 dmgDealtMul（祥子/边狱就是这么叠高的）。

## 3. 表现类型 → 引擎实现（设计调色板）

标记：✅ 现成一行搞定 · ◐ 用现成原语自己拼 · ⚠ 需要给引擎加钩子。

| 想要的表现 | 引擎做法 | 现成? |
|---|---|---|
| 攻击力↑/攻速↑ | `addBuff({mods:{atkPct, aspd}})` | ✅ |
| 伤害提升（乘算） | `addBuff({mods:{dmgDealtMul}})` | ✅ |
| 攻击附带法术/真实伤害 | `on('hit')` → `dealDamage({type:'arts'/'true'})` | ✅ |
| 单体→多目标 / 额外打N名 | `maxTargets` buff，或 `dealDamage` 轮询范围内目标 | ✅/◐ |
| 直线穿透 | 投射物沿线 `onHit` 多次，或 `forceAttack` | ◐ |
| **可转向投射物（剑气/音符）** | `addProjectile({steer:(p,dt)=>done})` | ✅(钩子已内置) |
| 投掷物/炸弹 | `addProjectile` + `onHit` 范围 `dealDamage` | ✅ |
| 召唤物/炮台 | `spawnToken` | ✅ |
| 布雷/陷阱/地面装置 | `spawnToken`(device) 或地面区域 | ◐ |
| **领域/地面持续伤害区** | `after` 周期循环对范围 `dealDamage` + `fx.zone` | ◐ |
| 增减益光环 | `on('tick')` → 给范围内单位 `addBuff` | ✅ |
| 击退/浮空 | `battle.push` | ✅ |
| 牵引（拉近） | `battle.pull` | ✅ |
| 自身传送/冲锋/撤回 | 位移自身（需确认 API，可能 ⚠） | ⚠ |
| 控制：晕/冻/眠/束缚/沉默/恐惧/寒冷 | `applyStatus(target, key, {duration})` | ✅ |
| 无敌/减伤/高防姿态 | `invulnerable` / `dmgTakenMul` / `defPct` buff | ✅ |
| 格挡数变化 | `blockCnt` buff | ✅ |
| 嘲讽/强制阻挡 | `taunt` buff / 相关 flag | ✅ |
| 护盾（抵若干伤害） | `addBuff({mods:{shield...}, shieldType?})` | ✅ |
| 反伤 | `on('damaged')` → 对来源 `dealDamage` | ✅ |
| 吸血/自愈 | `on('hit')`/`on('tick')` → `heal` | ✅ |
| **免死/复活/血不低于1** | `on('fatal')` → `ev.prevented=true` + `heal`（祥子但丁时钟/边狱） | ✅ |
| 群体治疗/回技力 | `heal` / 调 SP | ✅ |
| 驱散 | `removeBuff` / 清状态 | ✅ |

| 想要的表现 | 引擎做法 | 现成? |
|---|---|---|
| 弱点伤害（物/法取优） | 比较 `target.s.def/res`，`dealDamage` 选更划算的 type | ◐ |
| 按血量百分比伤害 | `dealDamage({amount: ratio*target.hp})`（带保底） | ◐ |
| 斩杀/处决 | 阈值判断 → `fatal` 或直接击杀 | ◐ |
| 无视防御/法抗（固定/比例） | `dmg.defIgnorePct/resIgnorePct` 或 flat | ✅ |
| 无视闪避 | `dealDamage({canDodge:false})` | ✅ |
| 中心>边缘差异伤害 | AoE 内按距离给 `dmg.mul` | ◐ |
| 递增伤害（蓄力越久越疼） | 技能 `INCREASE_WITH_TIME` + 随时长抬 `atkScale` | ✅ |
| **标记/通缉/点名** | 给敌人挂 buff/状态，索敌与伤害处读它 | ◐ |
| 改索敌优先级（打最低防等） | 特性 `targetPriority` / `sortEnemyTargets` | ✅ |
| 攻击全场被标记目标 | 自定义索敌遍历被标记集合 | ◐ |
| 蓄力瞄准狙杀（过杀即停/无视闪避） | `INCREASE_WITH_TIME` + 伤害递增 + 过杀判定 | ◐ |
| 延迟多锁定→齐射轰炸 | `after` 收集锁定，结束时一次性 `dealDamage` | ◐ |
| 弹药/子弹技能（打完结束/可中断） | 技能 `kind:'ammo'` | ✅ |
| 切换形态（toggle 两套数值） | S2 开关（见祥子 `_oblvnsOrgan`） | ✅ |
| 层数叠加（越叠越强） | `unit.mem.<key>` 计数 + 刷新 `addBuff`（见边狱 stacks） | ✅ |
| 在场时间/击杀成长 | `on('tick')`/`on('kill')` 计数 → buff | ✅ |
| 元素积累→爆发（灼燃/凋亡/神经/寒冷/腐蚀） | `dealDamage({type:'element', element})` 充能槽 | ✅ |
| 隐匿/潜行（不被远程选） | `applyStatus(..., 'stealth'/'camou')` | ✅ |
| 替身/分身 | 补位 standIn + `spawnToken` | ◐ |
| 全局计量槽（如 Fever） | `unit.mem.gauges.<name>` + 快照 `snap.fever`（见祥子） | ✅ |

> ⚠/◐ 的项不是不能做，是要么自己用现成原语拼（◐），要么像音符 `steer` 那样给引擎加一个小而通用、默认不生效的钩子（⚠）。加钩子的范式见 `mods/sakiko` 对 `projectiles.js` / `battle/events.js` 的改法。

## 4. 数值标尺（按商店阶 Tier 的正常区间）

来自现有非模组干员的分布：`p75` = 顶配但常见，`max` = 当前上限。**新干员的 atk/hp/def 与 DPS(=atk/bat) 不要超过同阶 `max`**；想做强，靠**机制**而不是裸数值堆顶（边狱那次就是裸数值 + 机制全家桶一起破格）。

| Tier | atk (p75/max) | hp (p75/max) | def (p75/max) | DPS=atk/bat (p75/max) |
|---|---|---|---|---|
| 1 | 530 / 921 | 2040 / 2530 | 290 / 516 | 422 / 502 |
| 2 | 574 / 728 | 1816 / 2895 | 297 / 495 | 406 / 478 |
| 3 | 577 / 875 | 1864 / 2938 | 311 / 530 | 462 / 702 |
| 4 | 671 / 1020 | 1760 / 2867 | 313 / 557 | 429 / 517 |
| 5 | 612 / 1362 | 2214 / 4947 | 343 / 514 | 458 / 640 |
| 6 | 616 / 1118 | 1959 / 2703 | 247 / 444 | 432 / 621 |

机制侧的「破格信号」（设计时自查，别一个干员全占）：无条件的乘算 `dmgDealtMul`、无条件双穿（def+res ignore）、给全队的免死/复活、以及把「高输出 + 高生存」堆在同一人身上。核心盟约（`isCore`）本身就带强力羁绊效果，成员数值更要克制。

## 5. 实操：把一个干员做成 mod

目录（装的是 `node tools/mod.mjs install <id>`，会把 `sim/` 拷进引擎、把 `data/*.json` 并入）：

```
mods/<id>/
  mod.json              # id/name/version/bonds/chess/garrisons…（装/卸的清单）
  data/chess.json       # 这条干员的完整记录（_a 和 _b）
  data/bonds.json       # 若新开盟约
  data/tokens.json      # 若有召唤物
  sim/kit.js            # kit（default export { [charId]: builder }）
  assets/…              # 立绘/spine/音频（拷到 public/assets）
```

步骤：

1. **写数据**：照 §1 填 `chess_char_*_a/_b`，确认 `stats` 落在 §4 区间，`bonds`、以及每个技能/天赋/特性的 **bb 数值**（这是 kit 的输入，务必准）。
2. **写 kit**：§2 契约。按 charId 注册；用 `skillRec/talentBb` 读 bb；三技能各自作者化；§3 挑原语实现表现。
3. **接线**：自选/通用干员走 `server/sim/content/kits/index.js` 的 `OPERATOR_KIT_FILES` 列表；模组 kit 走 `content/index.js`（仿 `SAKIKO_KITS = safeImport('./mods/<id>/kit.js')` 再并入 `KITS`）。
4. **安装 + 测试**：`node tools/mod.mjs install <id>`；写 `test/mods/<id>.test.js`，用 `test/helpers/battleHarness.js` 的 `makeBattle({units,enemies})` 跑一场，断言技能命中/伤害/不变量（范式见 `test/mods/sakiko.test.js`）。

## 6. 约定与常见坑

- **charId 驱动 kit**：同一 charId 的 `_a/_b`、乃至把一个重做版叠在旧棋子上（祥子就是用 `char_4182_oblvns` 的新 kit 驱动 ave-mujica 的 `chess_char_6_21_a`），都靠 charId 命中。
- **安装顺序决定覆盖**：`data/*.json` 是 `Object.assign` 合并，后装的覆盖先装的。要覆盖另一个 mod 的记录，就排在它后面装（祥子装在 ave-mujica 之后）。
- **别整仓覆盖**：外部仓库常是整个游戏的 fork，直接拷它的 `data/` 会**抹掉你装的所有 mod 和配置**（比如主盟约那套 `config.assist`）。永远按「只取需要的文件、并入 mods/」来做。
- **外部更新会冲掉引擎改动**：这个整合目录被更新时，`server/match/pool.js`、`player/economy.js` 等会被覆盖，之前加的能力（如主盟约刷新加权）会丢。更新后要回看并补回。
- **kit 必须被接线**：光把 `sim/kit.js` 拷进去不够——`content/index.js` 不自动加载任意 mod 的 kit（历史上 ave-mujica 的 kit 就因为没接线一直走通用兜底）。记得在 `KITS` 合并处加上。
- **数据 bb 要对**：天赋/特性/技能的数值全从 bb 读；bb 缺或错，kit 会读到默认/错值，表现「看着不对但不报错」。
- **加引擎钩子要通用且默认关**：像 `projectiles.steer`、`snap.proj/snap.fever`，不传就与原版完全一致，才不会动到别的内容；加完跑 `test/sim` + `test/render` 回归。
- **核心盟约标记**：`bond.isCore=true` 的是「主盟约」（含模组阵营罗德岛/边狱/Ave Mujica）；很多机制与数值平衡都读它。
